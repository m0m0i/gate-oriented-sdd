### What this cost, and why it is the interesting part

Four defects, each introduced by the fix for the one before it:

1. The transform collapsed YAML front matter and merged every heading into the paragraph below it.
2. The verifier could not see that, because `normalise` was `unwrap(unwrap(x))` compared against `unwrap(x)` — true by construction for any idempotent transform. It reported `0 changes` on a diff that broke three issue templates.
3. The indent rule that fixed a summary sentence being attached to the wrong bullet was too broad, and refused a legitimate column-0 join — leaving `unwrap.py` unable to reproduce its own output while AC1 still reported green.
4. Treating `<!--` as structural to fix one file made another file's content-bearing comment opener opaque, shipping a hand-wrapped paragraph in a template `init` copies into every project.

**Every one was caught by the reviewer and none by the tooling.** Three of the four were invisible to the rendering-equivalence check because the damage was never in the rendering — it was in the raw text a model reads as source.

### Decisions

- **0.4.1, not a retroactive 0.4.0 tag.** 0.4.0 was bumped in `ca7fab7` and never tagged; a tag made now would point at a tree containing #55's documents. Consumers move 0.3.9 → 0.4.1. #62 still owns the tag and the missing guard.
- **Fixes as rules, not edits**, three times: standalone `{{PLACEHOLDER}}` lines, the enclosing-column continuation rule, and standalone comment delimiters. Each time, patching the file alone would have left the next run to break it again.
- **AC1 restated as a fixed point** mid-run, in its own commit ahead of the work it judges — the convention filed as #59 after #55 got it wrong. Worth noting what it does *not* buy: a fixed-point criterion is satisfied by moving either side, so it reports green on a file edited to agree with the tool just as readily as on one the tool produced. That is exactly how defect 4 hid.
