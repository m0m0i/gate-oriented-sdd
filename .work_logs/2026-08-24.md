### Decisions

- **Fold red and green into one task (#10)** — contrary to the issue's own stated preference.
  `implement`'s loop already defines a task as a complete Red-Green-Refactor cycle, so the
  templates are the outlier and the loop needs no edit. Rules out the alternative of
  rewording "no half-tasks" and restructuring the per-task loop. All specs written this
  session already use the folded form.

- **Receipt provenance: record now, gate later (#9)** — ship `reviewed_by` and the `init`
  fix together; refusing `CLEAN` on a self-review becomes its own issue once `init`
  guarantees the reviewer is spawnable. Gating first would hard-block every new project's
  first `implement`, which is #8's failure mode in different clothes. Rules out doing both
  in one spec.

- **Lock guard tests live in `test-gates.sh`, header broadened to "gates and guards"** —
  rather than a second `scripts/test-locks.sh`. A second suite costs a CI step, an entry in
  the validator lists in two files, and a second place to look. **This is a judgment call and
  the spec says so**; the reviewer was explicitly invited to reject it and did not.

- **`--update` bootstrapping is out of scope (#19)** — creating a lock is a different act
  from refreshing one, with its own design questions (vendored or derived? what sources?).
  Rules out deleting the unpinned-rulebook workaround in #16's PR.

- **Hooks point at the repo's own `hooks/`, not a copy** — this repo is the source; a copy
  would drift, and a drifted copy means testing a stale version of its own enforcement. This
  is the one project where that is correct. Recorded in `AGENTS.md` because it looks wrong.

- **The dogfood rulebook ships unpinned** — a `rules-lock.json` under `.claude/agents/` used
  to disable verification of all six shipped rulebooks. #16 fixed that half; pinning still
  needs #19. Explained in three places so it is not tidied away.

- **`Source globs` excludes the manifests** — a version bump lands after the review and
  would re-stale every receipt. The cost is explicit: a manifest-only commit does not run
  the validators locally, and CI is the backstop. Recorded on #14.

- **Turned OFF `strict_required_status_checks_policy`** — with several PRs open, each merge
  made every other one `BEHIND`, so a chained merge could only ever land the first. What it
  costs: a PR can now merge green against a `main` it was never tested against. Reversible.

- **0.2.3 was tagged before the README fix, and the tag was left alone** — `CONTRIBUTING.md`
  says README edits do not require a release, so a docs commit after the tag is the policy
  working. Rules out moving a published tag.

- **Every review this session was `reviewed_by=inline`.** The reviewer is registered under
  `.claude/agents/` but was added mid-session and is not spawnable without a restart, so its
  procedure was run by the author of the diff. Both reviews found real defects, so the
  procedure has value — but **no independent reviewer has yet read any diff in this repo**,
  and the receipts say so rather than implying otherwise.

- **#18 was closed as COMPLETED, but the code it describes is unchanged.** The
  `[ -n "$globs" ] || globs='*'` fallback is still at `hooks/review-gate.sh:79`. It no longer
  bites *this* repo because `.steering/tech.md` now supplies `Source globs`, which may be the
  reasoning — but the issue's stated scope was any project with a partial install, and for
  those the receipt still invalidates itself. **Recorded rather than accepted silently**;
  needs an explicit reopen-or-justify.
