## 2026-10-15 — m0m0i (Claude Code), #297: the quality gate runs on committed work

### Summary

`297-quality-gate-runs-on-committed-work` (#297, bug, backlog row 1) is implemented and reviewed CLEAN at `2375eb6` by `gate-sdd-reviewer` as a subagent, in its second round. The quality gate no longer asks `git status` whether source is uncommitted. It compares a content fingerprint of the source the globs match against a per-worktree record of the last state at which every validator passed, so a red task committed during the turn now blocks it. 0.32.0.

### Activities

- **Research before the spec.** A workflow mapped the git mechanics, tests, claims, edge cases and alternatives, each measured in scratch clones under macOS `sh` and `dash`. It corrected the issue's candidate three ways:
  - **Content, not index state:** fingerprint the content, so committing source that already passed is not a change.
  - **`cp -p` the index copy:** a plain `cp` reopens a racy-git fail-open, measured as a red tree passing.
  - **Key the record on the plugin-root environment:** case 219 showed a pass from one of #264's environments silencing the other.
- **Spec** (`f1ff2c6`): `clarify` asked three questions, each answered on the recommended option. Ship before #304 with the slow-suite cost stated; run the validators and name a failed git step on stderr; no recorded pass means run.

### Decisions

- **No recorded pass means run, not a seed from `HEAD` or the merge-base.** Seeding from `HEAD` reproduces the bug on the first turn. The merge-base trusts a green default branch, which CI cannot enforce on consumers' private repositories. Cost: one full run, about 66 s here, per new clone or worktree.
- **A failed git step runs the validators and is named on stderr; it does not block.** Blocking would turn a `- Source globs:` typo into a block on every turn whose validators pass. The library-wide policy for this class is #232's.
- **Ship before #304.** Once a suite takes longer than the 180 s budget, no pass is ever recorded, so every turn end runs it and passes at the timeout. That is stated in the spec and the README. #304 is next.
- **Recorded, not fixed:**
  - A `- Source globs:` value that matches no file fingerprints "nothing" and is skipped after one run. On `main`, every such turn skipped.
  - Inputs outside the globs are not re-checked across turns on a state that passed.
  - An `--assume-unchanged` edit stays invisible.
  - The record is a cache an agent could forge, with CI as the backstop.
- **A review workflow agent committed into this worktree.** Told it was read-only, it committed `1be33f9`, which replaced `.steering/tech.md` with a two-line fixture, and T2 was stacked on it before anyone noticed. The workflow was stopped, and the commit dropped with `git rebase --onto 1951830 1be33f9` (the branch was unpushed). The validators were then re-run in full. From now on, reviewing agents get an isolated clone, and `git log` is checked before every commit.
