## 2026-10-17 — m0m0i, #320 implemented: init times the validators

### Summary

`320-init-times-the-validators` (#320) went from an approved spec to a CLEAN review and the 0.34.0 bump in one session: two tasks, two spec amendments committed alone ahead of the review fix, and 352 test-gates cases green. `init` step 4.1 now times its by-hand run of the `- Validators:` line and writes a `- Validator budget:` line when the suite needs one, before the quality gate first runs. A project no longer learns that its suite is over budget by being blocked.

### Activities

- **Spec (`fe99dec`, approved `a4c223c`)**: clarify asked three questions, and the maintainer took the recommended answer each time: the value is twice the time, capped at 590; an existing line is only raised, with a diff; a suite over 590 gets 590 and a warning.

- **Review round 1 (at `88a5eb5`)**: BLOCKED, with 1 HIGH. The pin covered only the rule sentence, so deleting the measurement left every validator green. There were three LOWs:
  - the gate's first run came before the line existed;
  - "step 3 rendered 600" was true only on Antigravity, and a bound set by a hook file got no warning;
  - Q1 overstated how far it agreed with #304.
- **Fix (`b56fa66`, spec `1d3f831`, `ef39898`)**: the pin now spans the whole run of sentences. Timing and the line come before the gate's single run, and the bound wording and its remedy are corrected. Round 2 at `b56fa66` was CLEAN (`a145bd6`). Bump to 0.34.0 in `94b02b4`.

### Decisions

- **The by-hand run is timed, not the gate's run.** On an upgrade the gate can skip on a recorded pass and time nothing.
- **Time before the gate's first run.** The pass record (`hooks/quality-gate.sh`) fingerprints the Validators and Source globs lines but not the budget line. A pass recorded before the line was written would let the later run skip, and a suite over 170 s would be blocked before any line existed.
