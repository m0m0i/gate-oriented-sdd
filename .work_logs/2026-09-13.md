### Decisions

- **Guard two claims, remove the third.** The version and the receipt counts have exact, cheap
  sources. The behaviour count's only source is running `test-gates.sh`, already the slowest
  validator — guarding it would double it every turn to check one integer. **One claim was made
  checkable and the other was made unnecessary**, and the second is the stronger fix wherever it is
  available.
- **Scope widened out loud.** #115's title covers one of the three drifts. The widening was
  recorded as a comment on the issue before the spec existed, with #48 and #97 as the precedent for
  treating `## Status` as one subject. An issue whose scope grows silently is what `sprint` exists
  to prevent.
- **Two findings filed rather than folded in**, on AC8's boundary: #133 would touch `skills/`, a
  shipped path, and owe a bump this spec says it does not carry; #131 is about the reviewer's own
  allow-list and landing it here would break one-issue-one-branch.
- **Two known gaps recorded rather than closed** in the guard's docstring — a trailing bare counter
  in Japanese, and English `cases` — each with the reason the obvious fix is worse. *An unrecorded
  known gap is how round 1's defect survived; a recorded one is a decision.*
- **What ships, stated precisely**: the version claim can no longer go stale **quietly**. It can
  still go stale — #133 owns prevention.

### The four rounds, and the one mistake under all of them

**Every finding was a check narrowed to the example that prompted it — and the example is always
the case that is already fixed.**

- **Round 1** — I scoped the fix to `## Status` because that is where the issue pointed. The same
  count was false **a section above**, in both languages, and the guard I wrote certified its
  absence over the whole file. *A scope drawn from where a defect was reported is not a scope drawn
  around where that defect lives.*
- **Round 2** — removing the count, I replaced it with "every path across the gates and guards".
  `67 paths` was false but **falsifiable**; `every path` is unfalsifiable and unsourced, and G-4's
  own case-7 history is this repo's evidence that coverage is not exhaustive. And the Japanese half
  of the pattern required the noun **flush against the digits**, which is the least common way
  Japanese writes a count — the one form it caught was the one that had shipped.
- **Round 3** — the no-op detector in a fixture used `str.replace(x, x)`, the identity function,
  then concatenated: it could never fire. The *shape* of a guard with the substance removed.
- **Round 4** — clean.

## 2026-09-13 (second session) — m0m0i

### Summary

#127: `init` armed the document-set gate red on every first install. Fourteen commits, **0.8.0**,
test-gates 79 → 81 with a new skip mechanism. Eight review rounds — the code was right after two
of them, and the other six were about claims.

### Activities

- `127-init-arms-the-document-set-gate-red` (#127). `init` step 3 wrote `- Mode:`, copied
  `check-document-set.py` onto the project's `- Validators:` line, and created **none** of the
  three documents that checker requires. CAP-4's falsifier stated literally, and **dormant**:
  `quality-gate.sh` runs that line only when a `- Source globs:` path changed, and a document is
  never source, so the install looked clean and fired on the user's first real edit.
- **Root cause was a seam, not a missing `mkdir`.** The checker asked two questions through one
  exit code — *is the harness installed correctly* (which `init` can make true) and *has this
  project authored its documents* (which it cannot, without writing the user's thinking for them).
- `- Mode: bootstrap` added: claims the install-time invariant only, says so in its own success
  line, and **expires at the first spec**.
- Two fail-open defects found in review, both in the new code: `Path.is_file()` swallowing
  `OSError` one level inside a function whose docstring forbade exactly that, and
  `follow_symlinks=False` producing a *fourth* outcome in a function claiming three.
- `note_skip` in `test-gates.sh`: thirteen self-disabling guards used to report `ok`, two of them
  for whole cases. Applied to all thirteen, including the four that predate this spec.

### Decisions

- **A third declared state, not scaffolded documents and not a tolerant checker.** Running
  `prd`/`design-doc`/`backlog` inside `init` turns install into a multi-hour interview, against
  `init`'s own "treat a greenfield repo as the special case"; placeholders are the `TODO` step 3
  forbids one directory over; leaving the checker off `- Validators:` is the gate switched off at
  install and never switched back on. **Declared, not inferred** — for the same reason `minimum`
  is.
- **The grace period ends at the first spec**, not at the first merged one. A PRD starts being
  cited the moment a spec exists, so the block lands *inside* the flow with the cause one command
  behind the user — which is what CAP-4 actually asks for. It is not "never block"; it is never
  block on a failure that predates them.
- **0.8.0, minor**, on #110's precedent (a value on a machine-read line, and `init` writes
  something different). Rejected 1.0.0: #82 shipped, so the relocation holding the major is done,
  but this changes the installed interface in the same breath as declaring it frozen.
- **AC1 narrowed at round 4**, from *every validator `init` arms* to the one the fixture runs.
  `check-steering-anchors.sh` is armed by step 3 and neither installed nor run by `init_tree`.
  Stated in Design as **armed but unexercised** rather than closed — it is this issue's shape one
  axis over, and worth its own issue.
- **A correction to yesterday's habit, and to a commit on this branch.** `c6a30d9`'s message
  described four fixes; its diff carried two, because the edit script's single write came after a
  raise. That is #126's defect — *a commit that claimed two fixes and made neither* — and it
  happened again here. The commit stands unamended: rewriting a post-mortem would lose the record.
  `f50bf45`'s own message then overstated the mechanism ("both discarded" when one of three
  landed), which the reviewer caught and which this entry corrects.
- **Six of eight rounds were about claims, not code** — a count, a derivation, a commit message,
  four line pointers, and a sha I wrote from memory rather than from `git log`. Recorded in
  `observations.md` because the lesson is not "count more carefully": **a number, a pointer or a
  sha is a claim, and a claim needs the same derivation a gate does.**
