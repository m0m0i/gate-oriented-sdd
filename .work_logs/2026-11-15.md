### Decisions

- **The exclusion at push time asks the destination, not the clone.** `pre-push` runs `git ls-remote` on the URL git gives it. The remote-tracking refs hid commits when a push URL differed from the fetch URL, and hid the whole old history after the destination was rewritten. It costs one round trip per push, 2.0 s against GitHub.
- **A snapshot, not the main checkout, serves a branch with no hooks.** The first Design fell back to the main checkout's scripts, which would have refused every commit in older worktrees until that checkout was updated and could have run another session's uncommitted edits.
- **The shim carries a version, and a newer installed one passes.** Byte identity across twenty worktrees on different branches has no single answer.
- **Every input is scanned as the lines it holds.** The third review found `--commits` scanning added lines with the patch's `+` in front, so a `^`-anchored expression matched none. `--refs` had the same shape with `refs/heads/`. Both were reproduced red before the fix (`e2c5566`).
- **Each review round's HIGH was a real defect**, so the rounds went on to a CLEAN verdict and stopped there. Round one: an empty `core.hooksPath` passed the hook check while git ran no hook (measured). Round two: a case that could not go red for its check. Round three: the `+`.
- **Mutation, not reading, is what showed a case could fail.** Removing each pinned git option in a scratch copy turned its own half red. One half stayed green with the path stream removed, because a second file's `+++` line stood in for the path; it needed a commit that adds only an empty file. A `sed` alternation that BSD `sed` does not take left the push exclusion empty, which only a "what the destination already holds is not rescanned" half caught.
- **Recorded from the fourth round, not fixed**, since a source change would stale the receipt:
  - MEDIUM: the message reads do not pass `--encoding=UTF-8`, so `i18n.logOutputEncoding` set to another encoding could change the bytes `--commits` scans. Not reproduced. Exposure is a push of commits made past the commit hooks in a clone with that setting; CI runs with default configuration. Worth an issue.
  - LOW: a `^`-anchored expression that hits a commit's path fails the run but is reported "at a place the second read did not find". Fails closed.
  - LOW: a branch literally named `refs/tags/x` is scanned as `x`. No private word is removed.
  - INFO: a CR before a line end in a commit message defeats a `$`-anchored expression, as it does over a CRLF file in the tree. git strips trailing whitespace after `commit-msg` runs, so a `$`-anchored hit can first appear at push. A merged signed tag's `mergetag` header is not in `%B`.
- **AC12 is met with exceptions.** Eleven refusals have no case of their own, and each stays closed if removed: the tag-read, object-type, no-object and batch-check refusals in `pre-push.sh`, two in the hook check (no version line, no common directory) and four in the installer (not a repository, no version line, a missing script, an unwritable hooks directory).
- **AC10 is a measurement, not a case** (ADR-12): 0.18 s against 0.03 s for a commit, 1.78 s against 0.27 s for a clean push of 199 commits, 6 s to locate four hits among 277 commits. The suite ran in 273 to 306 s over five full runs, against the 336 s budget, which is not raised.
