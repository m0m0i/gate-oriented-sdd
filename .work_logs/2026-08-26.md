### Decisions
- **The templates gave way, not the rule.** `implement`'s loop already defined a task as a complete cycle, so folding the templates was the smaller edit to the document that was wrong. Rules out the issue's own preference — redefining "one task, one commit" — which needed "no half-tasks" reworded and the per-task loop restructured.
- **The guard is on the Validators line, not only in CI.** A guard in CI alone is enforced by the half of this harness that cannot end a turn. Demonstrated: reverting the fold makes `quality-gate.sh` exit 2 and emit `{"decision":"continue"}`, both naming the guard.
- **`TASK_LINE` matches any `- [ ]` line, not `T\d+:`.** Over-inclusion here can only produce a false flag, which is the fail-closed direction. Under-inclusion let `- [ ] **T1:** …` parse as nothing at all.
- **Accepted rather than fixed**, both argued by the reviewer as out of scope: a code span opened and closed inside a word can still clear a red line (not writable prose; closing it costs more than the boundary is worth — now recorded beside the regex), and case 37's `chmod`-ineffective branch reports `ok` having asserted nothing (#39's first item, and `report` still has no `skip`).

### The pattern worth keeping, because it repeated
Every real finding in four review passes was **the anchor's own shape inside the code written to enforce the anchor** — and each was found by a *mutation*, never by an ablation:

1. A section contributing nothing was skipped: the floor checked that a `## 3. Tasks` heading had produced a **key**, which `setdefault` creates whether or not a line parsed under it, and the emptiness check was **global**. One section could contribute nothing while the others kept the total non-zero.
2. Every fixture varied only the Feature block, so narrowing the guard to scan Feature alone deleted half its work-set with the whole suite green.
3. The fix for a path-citation hole applied prose-stripping to **both** patterns, which reopened two narrower holes. Stripping before the *clearing* pattern can only make a guard louder; stripping before the *accusing* pattern can only make it quieter.

Two lessons, both in the spec's §4:
- **An ablation removes a branch you wrote; it cannot find a work-set no fixture exercises, nor a fix that traded one hole for two.**
- **Normalisation applied to both sides of a test is not symmetric.**

Also recorded honestly: §4 first claimed a mutation reddened two cases when it reddened one. The reviewer caught it, and the error ran in the direction that flatters the work — the same shape as the stale counts this branch swept.
