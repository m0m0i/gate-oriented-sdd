## 2. Design (HOW)

- Approach, and the order of operations: three commits after this spec, each green, in this order. **First the case** that pins the guard's remedy heading to the skill template and to this repository's own document — it passes on the merge-base, which is the baseline a rename needs and does not have today. **Then the placement**, alone: the guard is red on `main` for #209 unplaced and goes green with the row, which makes `check-backlog-tracker.py` the failing test for that commit. **Then the rename**, as one vocabulary-only diff a reviewer can read as a substitution: the two skills, the guard's constant and its remedy string, the fixtures in `test-gates.sh` that print or assert the old heading, the two docs, the steering note, the CI comment, and every use in `docs/BACKLOG.md`. Case 145's literal `*"Discharged since last grooming"*` is renamed rather than made to read the constant: that case exists to assert the message against a literal "rather than prose nobody compares", and turning it into a self-comparison would remove the assertion.
- Affected files: `scripts/test-gates.sh` (one new case beside case 145; three fixture literals and one `Last groomed` line in `bt_repo` renamed); `docs/BACKLOG.md` (row inserted, rows renumbered, references moved, then vocabulary); `skills/backlog/SKILL.md`; `skills/sprint/SKILL.md`; `scripts/check-backlog-tracker.py` (the constant and the remedy sentence at `:349`); `docs/verified.md`; `docs/layout.md`; `.steering/tech.md`; `.github/workflows/ci.yml` (a comment). Two shipped paths move, so `check-version-bump.py` will ask for the bump in CI.
- **Coverage gap:** the guard's constant is, in its own comment, "named here and read NOWHERE" — the remedy is the only automated instruction anyone receives about a discharged row, and "a heading that drifts from the template turns that instruction into a wrong address". Nothing compares the two today, and a rename is exactly when they drift: rename one and the message sends every consumer to a section that does not exist. The new case reads `DISCHARGED_HEADING` out of the script with `sed` and asserts it is a whole line in `skills/backlog/SKILL.md` and in `docs/BACKLOG.md`. It passes on first run, so the case carries a mutation record in case 145's form: which file was renamed alone, which check flipped, reverted. A `check-skill-contracts.py` needle was considered and rejected — it pins one string in one file, and the property here is equality across three.
- The renumber, and how it is checked: two tests from the #182 and #174 renumberings. A row that cites its own position is wrong by construction, so none may. And every `row N` / `rows N, M` / `below N` / `above N` in the table and under `## What would change this order` is listed before and after, and each must resolve to the same item — that list is written into the commit body, not into this document. The `## Record of …` sections describe positions as they stood at their date and are not renumbered.
- Risks: a `git add -A` would sweep in an untracked `.specs/207-…/` draft that is not this branch's — files are added by path. The slug at `docs/verified.md:165` is one substitution away from becoming a dead path — AC4 is the guard, and the substitution is run with a word boundary and then checked against that line. The 71 uses in `docs/BACKLOG.md` include quoted strings that name the *old* heading as the thing a past refinement did or did not add ("did not add a `## Discharged since last grooming` section") — those rename too, since the document is describing its own current section by name, and a reader of the live document should find the heading it points to.
- Rollback: revert the three commits. Nothing persists state on the new wording except a consumer's `BACKLOG.md`, whose headings the guard never reads, so an installed document with either heading keeps passing.
