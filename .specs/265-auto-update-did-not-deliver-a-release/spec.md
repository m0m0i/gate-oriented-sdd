  - **U1 — 0.23.0 did not reach the machine for three hours.** #265's timeline. The 21:46:14 `lastUpdated` came from V3's `claude plugin install gate-sdd@gate-oriented-sdd --scope project` at 21:46:03, an install by `<plugin>@<marketplace>`, which refreshes that marketplace whatever its auto-update setting (`plugins/loading`). 0.23.0 merged at 2026-10-07 03:25:07 and was published at 03:29:59. A terminal session on 2.1.292, first message 06:37:28, found the clone and both installs at the previous version.   - **U2 — a session the Claude desktop app starts runs no pass.** Three desktop-started processes on 2.1.293 held `DISABLE_AUTOUPDATER=1` and `CLAUDE_CODE_ENTRYPOINT=claude-desktop`. A terminal `claude` held neither, and neither is set in a shell profile or user settings. The two documented sentences: the pass is off under `DISABLE_AUTOUPDATER=1` unless `FORCE_AUTOUPDATE_PLUGINS=1` (`plugins/loading`), and `FORCE_AUTOUPDATE_PLUGINS` exists "to force plugin auto-updates even when the main auto-updater is disabled via `DISABLE_AUTOUPDATER`" (`env-vars`). V3's debug log, from a 2.1.290 run started in a desktop session's shell and so carrying its environment, has `Plugin autoupdate: skipped (auto-updater disabled)`. This spec's desktop session sent its first message at 2026-10-08 09:38:46, 7.6 minutes after 0.24.1 was published, and no marketplace was refreshed in the next ten minutes.
  - **U3 — a terminal session's pass, seen once.** On 2026-10-08 `lastUpdated` moved at 08:52:24 for `claude-plugins-official` and at 08:52:28 for `gate-oriented-sdd`, the two marketplaces with auto-update on. The two with it off did not move. A terminal session restarted at 08:42:48 had sent its first message at 08:44:31, 7.9 minutes before, and no other terminal session typed in those ten minutes. Nothing newer than the installed 0.24.0 had been released, so the pass installed nothing.
  - **U4 — #265's window and 0.24.1's, read against U2 and U3: no session that runs a pass started in either.** From 0.23.0's release to 06:37:28, the sessions with typed messages were desktop sessions and none from a terminal. At 2026-10-09 02:12 the clone and the user-scope install were at 0.24.0 and `lastUpdated` was still 08:52:28. Every session typing since the release was a desktop session or U3's, whose pass had already run.
  - **R1 — `/reload-plugins` does not rerun `SessionStart`.** In a terminal session on 2.1.293 that started under 0.23.1, `claude plugin update` moved the user scope to 0.24.0 at 04:57:39 on 2026-10-08. After `/reload-plugins` at 05:36:29, the first session's Bash had it unset at 08:27:45. 0.23.1's hook writes no variable, so 0.24.0's `SessionStart` hook had not run.
