# Spec: a discharged row has one place to be written down

- Slug: 174-a-discharged-row-has-no-home   Issue: 174   Type: feature   Status: done
- Author: m0m0i   Date: 2026-09-21

## 1. Requirements (WHAT / WHY)

- User story: As someone opening `<docs>/BACKLOG.md` at the start of a grooming, I want one section naming every row that has left the list since the last grooming — the issue, the position it held, when, and how — so that I can see what moved by reading this document alone, and so that a row which ships whole leaves a trace at all.
- Serves: **CAP-6** (LV-4) — planning that terminates in something the harness reads. `sprint` reads this document at step 1 (`skills/sprint/SKILL.md:24`), and in a `minimum`-mode project it is the queue specs are written from. It is also the capability this change is in tension with, which the Design has to answer rather than assume: a section nothing mechanically reads is CAP-6's falsifier in miniature, and `check-backlog-tracker.py` is the only mechanical reader this document has.
- Why the document cannot answer the question today: there is no section for a row that left, so the trace lands wherever the grooming can find a home for it. **Five places, not the four the issue names:**
  1. **A surviving row's `Why here` cell** — "#146 left this row by shipping" (`docs/BACKLOG.md:111`). Survives only until that row is rewritten, and exists only when a row survived. A row that ships whole has no cell: #131 left row 1 that way on 2026-09-20, and #182 left row 2 the same way on 2026-09-21.
  2. **`## What changed at this grooming`** (`docs/BACKLOG.md:16`) — overwritten by the next grooming unless it is preserved wholesale.
  3. **`### Triggers that have already fired`** (`docs/BACKLOG.md:58`) — only reachable when the row carried a conditional, and it records the trigger rather than the discharge.
  4. **The day's work log** — outside the document entirely, so it answers the question only for someone who already knows which day to read.
  5. **The preamble** (`docs/BACKLOG.md:5`) — the fifth place, which did not exist when the issue was filed. The 2026-09-20 between-grooming correction had no section to go in, so it became a preamble bullet; the eighth grooming could not delete it and could not leave it standing either, and marked it *"Superseded by the eighth grooming, which discharged that row — kept as the record of the first correction the check ever made."* The first correction `scripts/check-backlog-tracker.py` ever prompted landed in the one part of the document every reader reads first, and it is now a dated record sitting above the live preamble. This is the issue's own argument arriving one place wider than the issue predicted.
- What the scatter costs, measured on this document: preserving a record wholesale is the only way to keep it, so the file now carries **three** appendices — `## Record of the seventh grooming` (`:84`), `## Record of the sixth grooming` (`:126`), `## Record of the fifth grooming` (`:144`) — and they are 27% of the file by size, against 41% for the ordered table itself. The issue predicted this at one appendix and called it the wrong shape; two more have been added since it was filed, and the seventh grooming declined to fix it in passing because *"shipping its design here would settle an open question inside the document it is about"* (`docs/BACKLOG.md:96`).
- Why the hand-written discharge is also wrong, not just scattered: the eighth grooming discharged one row and *"renumbering twenty-two positions, five `Blocks` cells and eight prose references by hand, and getting the `Blocks` column wrong once on the way by applying the renumber twice"* (`docs/BACKLOG.md:21`) followed from it. Row 1's own cell states the conclusion: **a row that has to be discharged by hand is a row that will be discharged wrongly.** This spec does not fix the renumber; it removes the part of the discharge that is a free-text judgment about where to write it.
- Where the template stands today: `skills/backlog/SKILL.md:41-63` defines the preamble, the ordered table, `## Unshaped` and `## Open, not planned`. It defines **no** `## What changed at this grooming` and no record section of any kind. Both are inventions of this repository's own groomings, so the document runs ahead of its own template — #74's defect in the opposite direction, and the reason the issue's AC4 cannot be executed as written (see AC4 below).
- Impact: every project running `backlog`, in both modes. Here it is the mechanism behind the lead finding of four consecutive groomings, it was filed from the sixth and has held row 1 since the seventh, and the eighth's verdict on it is *"Row 1 has now been argued for by five consecutive groomings and has never been built"* (`docs/BACKLOG.md:21`).
- Acceptance criteria:
  - [ ] **AC1:** WHEN the template at `skills/backlog/SKILL.md` is rendered THE SYSTEM SHALL provide a `## Discharged since last grooming` section carrying one line per row that left, and each line SHALL state four things: the issue, the position the row held, the date it left, and how — shipped by a named closing pull request, closed without shipping, or folded into a named row. A line missing any of the four is not a discharge record, because each of the four is the question a later reader asks first.
  - [ ] **AC2:** WHEN a grooming runs THE SYSTEM SHALL be instructed to prune that section to **the two most recent groomings' worth of lines**, dropping older ones — a stated condition rather than a matter of taste, so the section cannot grow into the second history the three appendices already are. _The issue's wording, "after the archived specs have absorbed the detail", is replaced: `archive` is a sweep run on request rather than a step of the flow, so a prune conditioned on it is a prune with a manual precondition and would never reliably fire. Decided without asking; the reasoning is #182's out-of-scope note applied one document over._
  - [ ] **AC3:** WHEN a discharge is recorded between groomings THE SYSTEM SHALL have it append to this section and change nothing else — a bounded edit, not a re-groom. #79 has shipped and settled who: no skill runs at either door (`skills/backlog/SKILL.md:20`), `sprint` writes issue numbers onto rows it took and nothing else (`skills/sprint/SKILL.md:33`), and `scripts/check-backlog-tracker.py` reports the drift for a person to act on. So this criterion binds the **reader of that report**, and the instruction SHALL sit where that reader is looking. _Amended 2026-09-21 after review round 2: "change nothing else" is about judgment — no order revisited, no reasoning rewritten — and read literally it forbade the position shift that dropping a row unavoidably causes. The shipped sentence says both, and the criterion now matches it; the renumber stays out of scope._
  - [ ] **AC4:** the template SHALL also define `## What changed at this grooming`, scoped to **judgments** — what moved and why, what was re-argued, what the grooming deliberately did not do — so that a row discharged by shipping is never the only content of that section. The issue states this as narrowing existing guidance; there is none, because the section exists in this repository's document and in no template, so the criterion is met by defining the section and its scope in one edit (clarification 2). The two sections SHALL be distinguishable by what goes in them, not by tone: facts about rows that left go under AC1's heading, and a grooming whose entire record is "row 1 shipped" has recorded no judgment at all.
  - [ ] **AC5:** every rule and red flag in `skills/backlog/SKILL.md` SHALL reference a section the template defines, verifiable by reading the rules list against the template fence. Two do not today — *"Every 'Next up' row states why now"* (`:76`) and *"Nothing is in 'Not ready'"* (`:87`) — and both are closed here rather than left to #164 (clarification 4). This discharges **#74's second bullet**; its first (the walking skeleton with no skeleton) and third (the `Blocks` column form) stay open, so #74 does not close on this branch and **#164's AC6 becomes a no-op it drops on rebase**.
  - [ ] **AC6:** WHEN `scripts/check-backlog-tracker.py` reports that an `Item` cell cites a closed issue, its remedy SHALL name `## Discharged since last grooming`. Today it says *"move the citation into `Why here` if it is now history"* (`:301-305`) — which is place 1 of the scatter, prescribed by the only automated instruction anyone gets about a discharged row, and unavailable in exactly the case that produced this issue: a row that ships whole has no surviving cell. The remedy SHALL name both outcomes and say which is which — the row survives and the citation moves to `Why here`, or the row is discharged and the line is appended above. This is the section's mechanical reader, and it answers the CAP-6 tension rather than recording it (clarification 1).
  - [ ] **AC7:** the new section SHALL buy no issue an exemption. An **open** issue named in a discharge line — a row folded into another, whose issue is still live — SHALL still be reported as absent unless a row cites it. A section that quietly exempts is the `## Open, not planned` fail-open the guard already reasons about at `:73-83`, arriving through a new door; it holds by construction today and the point is that it SHALL still hold after the section exists. (`- Owns: gates never fail open`.)
  - [ ] **AC8:** `docs/BACKLOG.md` SHALL carry the section, populated from the discharge the eighth grooming has already recorded — #182, row 2, 2026-09-21, shipped as #186 — so AC1's four fields are demonstrated on a real discharge rather than asserted. This is a migration, not a grooming: no order is revisited, no reasoning rewritten, and no row placed (clarification 3).
  - [ ] **AC9:** AC6 and AC7 SHALL each have a case in `scripts/test-gates.sh` that is **red-capable** — it fails before the change, or, where the path already exists, under a **named mutation** that removes the specific refusal the case asserts, with the mutation and what it flipped recorded per case. Each case SHALL assert on the exit code **and** on the message, because a checker that does not exist also exits non-zero — the contract case 85 states. No pre-existing case SHALL change verdict.
- Out of scope:
  - **Who performs the edit after a sprint or a merge.** That is #79, which has shipped; AC3 consumes its answer rather than reopening it.
  - **Version lines, the `Serves` column, the `Blocks` form, and the `minimum`-mode step 1.** That is #164, which edits the same template and rebases onto this. Its AC6 is the one place the two overlapped and AC5 takes it; the rest is untouched here.
  - **The renumber.** Discharging a row shifts every position below it and every `Blocks` cell and prose reference that names one; the eighth grooming got it wrong once. Real, adjacent, and not this issue — it is the part of the discharge that needs a tool, and this issue is the part that needs a home. Not filed here and not recorded in a follow-up section of this spec: row 1's own cell and `docs/BACKLOG.md:21` already carry the argument, and a third copy is the drift this repository keeps finding.
  - **Migrating the three appendices.** They are dated records and stay. AC2 governs what the new section accumulates from now on, not what the old ones hold.
  - **The ordered table having no heading of its own.** In the template it needs none, because it follows the preamble directly; in this document the grooming records have pushed it to `:98`, where it sits inside `## Record of the seventh grooming` and "under the table" is no longer a location the template's own ordering predicts. Found while writing AC1 and left alone here — it is a defect of this document, not of the skill.
  - **Closing or filing issues.** `backlog` creates none (`skills/backlog/SKILL.md:71`), and this spec does not change that.

## 2. Design (HOW)

- **Approach.** Three edits and one migration, in the order the Tasks run them.

  1. **The guard's remedy names the section** (`scripts/check-backlog-tracker.py`). This is the load-bearing decision and the reason the change is not prose. The only automated sentence anyone ever receives about a discharged row is the finished-direction remedy at `:301-305`, and today it prescribes place 1 of the scatter — a cell that does not exist when the row ships whole. Rewritten, it becomes the one place the section is *reachable without reading the skill*: the guard reports the drift, and its own message says where the answer goes. Nothing about the guard's verdicts changes — same condition, same exit code, same issues named — so the blast radius is one f-string and the cases that read it.
  2. **The template gains two sections** (`skills/backlog/SKILL.md`), placed between the ordered table and `## Unshaped`: `## Discharged since last grooming` first, then `## What changed at this grooming`. Facts above judgments, both under the thing they are about. They go before `## Unshaped` rather than after `## Open, not planned` because the question they answer — *what happened to this list since I last looked* — is asked before the queues, and because AC1's section is what the guard's new remedy points at, which reads badly if it points past two other sections.
  3. **The rules and red flags are reconciled** to the sections that now exist (AC4, AC5). `Next up` becomes the per-row `Why here` the template actually has; `Not ready` becomes `## Unshaped`, which is the section that already holds work with unresolved dependencies.
  4. **`docs/BACKLOG.md` receives the section** (AC8), populated from the eighth grooming's own record and nothing else.

- **Key decisions taken without asking.**
  - **No twenty-sixth entry in `scripts/check-skill-contracts.py`.** The cap is deliberately sticky — the module docstring requires the spec proposing an entry to argue why review cannot defend the sentence instead — and that argument cannot be made here. The candidate sentence is the judgments-only scoping of AC4, and it sits inside the template fence, which a reviewer reads as a unit; a diff removing it is a diff removing a line from a template, which is exactly the shape review catches. The load-bearing half is carried by AC6's remedy instead, and that one review *cannot* silently revert, because AC9's case asserts the message.
  - **A discharge line is a bullet, not a table row.** `ROW` matches `| <digits> |` anywhere in the file (`scripts/check-backlog-tracker.py:49`), so a second table would silently join the generous region of the absent direction and hand every issue it names an exemption. AC7 is that hazard stated as a criterion. _Corrected after review round 3, which caught this sentence claiming the bullet form is "structural rather than a rule someone has to remember":_ nothing is structural about it. It is a rule, in prose, in the template body where the person about to draw that table is looking — and `ROW` will match a discharge table the day one is written.
  - **A rescoped row is not a discharge.** It did not leave; it was retitled, and its position still exists. It belongs in `## What changed at this grooming` with the rest of the judgments. The issue raises this as an open question and answers it in the asking; recorded here so the template can say it in one clause rather than leave the next grooming to re-derive it.
  - **The version bump is minor, not the patch the issue's footer predicts.** Two new template sections change what a grooming produces, which is a flow change by the rule the last two releases followed (0.15.0 → 0.16.0 → 0.17.0, both for one shipped behaviour each). The footer was written when the scope was one section of prose. The bump is a **step** of `implement`, not a task — #113.

- **Affected modules and files**, per `.steering/structure.md`:
  - `skills/backlog/SKILL.md` — shipped. Template fence (`:41-63`), the rules list, and two red flags. AC1–AC5.
  - `scripts/check-backlog-tracker.py` — not shipped. One message. AC6.
  - `scripts/test-gates.sh` — not shipped. One case beside the four existing `check-backlog-tracker` cases. AC9.
  - `docs/BACKLOG.md` — not shipped. One section added. AC8.
  - `plugin.json` and `.claude-plugin/plugin.json` — the bump, as a step.
  - `.work_logs/2026-09-21.md` — a step.

- **Contract changes, and who else consumes them.**
  - `skills/backlog/SKILL.md`'s template is consumed by every project running the skill, and by `scripts/check-backlog-tracker.py`, which locates `## Unshaped` and `## Open, not planned` **by heading text** (`:67-68`). Neither heading moves and no third heading is added to that list: both new sections are outside both citation regions. AC7 asserts that and AC9 proves it **for the discharge section only** — `## What changed at this grooming` holds by the same construction and is unpinned, which is the accepted gap recorded in round 3's triage.
  - `sprint` reads this document at step 1 and writes issue numbers onto rows it took (`skills/sprint/SKILL.md:33`). It is untouched — a discharge is not a row it took — and its pinned contract sentence is not edited, so `check-skill-contracts.py` is unaffected.
  - The guard's remedy string is read by CI, by hand-run groomings, and by AC9's case. It is the only consumer that changes.

- **Risks and trade-offs.**
  - **A section nothing parses is a section that rots.** Mitigated rather than eliminated: the guard points at it but does not validate its contents, so a grooming can still write a line missing one of AC1's four fields. That was the third option in clarification 1 and was rejected on LV-2 grounds. The honest statement is that AC1 is a prose contract with a prose enforcement, and the mechanical part is only that the instruction to use it is unavoidable.
  - **Two new sections in a template that already runs behind its document.** This closes the gap for these two and leaves `## What would change this order`, `### Triggers that have already fired` and the three `## Record of the Nth grooming` appendices still undefined by the template. Stated rather than implied: this spec does not claim the template and this document now agree, only that they agree about the two sections a discharge can land in.
  - **AC8 edits a document a guard reads on every pull request.** `check-backlog-tracker.py` runs in CI on this branch, so a malformed migration turns this spec's own pull request red — which is the desired direction, and the reason AC8 is a task rather than a follow-up.
  - **Pre-existing red.** `docs/BACKLOG.md` must still satisfy the guard after AC8. #184 and #185 are already placed under `## Open, not planned`, so the tree is green today; filing anything new mid-branch would redden this pull request through no fault of the change.
