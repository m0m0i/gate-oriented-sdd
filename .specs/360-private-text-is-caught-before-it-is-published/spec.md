# Spec: private text is caught before a commit or a push publishes it
- Slug: 360-private-text-is-caught-before-it-is-published   Issue: 360   Type: feature   Status: approved
- Author: m0m0i   Date: 2026-11-15

## 1. Requirements (WHAT / WHY)
- User story: As the maintainer of a public repository extracted from private work, I want a private word stopped on my own machine before `git` publishes it, so that a history cleaned once stays clean.
- Serves: M-1 in `docs/CONTRACT.md` (no private context in the tree) and `- Owns: gates never fail open`. No capability in `docs/PRD.md`.
- Why the working-tree guard is not enough, measured on `main` at `16716cd`:
  - `scripts/check-leakage.sh` reads the working tree only (#357's Out of scope). A commit message, a file added in one commit and removed in a later one, and a branch or tag name never pass it.
  - CI runs on a push to `main` and on a pull request, so on a public repository it reports text that is already public. A ref name is public the moment it is pushed, and no ruleset available to a personal repository can refuse one by pattern.
  - No git hook exists in this repository: `core.hooksPath` is unset and `.git/hooks` holds only samples.
- Acceptance criteria:
  - [ ] **AC1:** `scripts/check-leakage.sh` scans one of four further inputs when asked, with the tiers, the pattern file, the faults and the exit status #357 gave the working-tree scan (its AC2 and AC4): what the next commit changes, which is each staged path and its staged content; text on standard input; a set of commits, with each commit's message, each path it adds and each line it adds; and a list of ref names on standard input. The last three also run in a bare repository. With no mode argument it scans the working tree as today.
  - [ ] **AC2:** WHEN one of those inputs matches THE SYSTEM SHALL report the tier and a location, and nothing else: the input's line numbers; a commit's short id with the message's line numbers, or with the path and its line numbers; a ref's position in the list. Neither stream holds the matched text, the pattern, a path that matched or a ref name that matched.
  - [ ] **AC3:** WHEN the guard cannot read what it was asked to scan THE SYSTEM SHALL exit 1 and name the fault: a revision git cannot resolve, a git command that exits non-zero, an object it cannot read, a path git quotes, a shallow repository, a run outside a repository, or standard input that is a terminal. An input that was read and is empty passes, and the report says it held nothing.
  - [ ] **AC4:** WHEN `git commit` runs in a clone with the hooks installed and the message, a staged path or staged content matches a failing pattern THE SYSTEM SHALL refuse the commit. This holds for a commit of named paths, for the new message and newly staged changes of `--amend`, and for the message of a merge commit. What an amended commit already held, and what a merge brings in, are AC5's.
  - [ ] **AC5:** WHEN `git push` runs in a clone with the hooks installed THE SYSTEM SHALL refuse the push before anything is sent if a failing pattern matches a commit the destination does not hold, a branch or tag name being published, the message of any annotated tag being published, or a blob a pushed tag points at. This holds for a commit whose text a later commit in the same push removes; for commits made by `cherry-pick`, `revert`, `rebase`, `merge` and `commit-tree`, which run no content hook; and for commits the clone's remote-tracking refs still list after the destination's history was rewritten. Deleting a remote ref is not refused.
  - [ ] **AC6:** one command installs the hooks for a clone and every worktree of it, and they then run in a worktree whose branch was cut before the hooks existed, whichever branch the main checkout is on. Run again, it changes nothing or brings the installed copy up to date. It refuses to replace a hook file it did not write, and to install over a newer version of its own.
  - [ ] **AC7:** WHEN the working-tree guard runs in a clone whose hooks are missing, are not executable, are older than the worktree's, were edited, or are bypassed by `core.hooksPath` THE SYSTEM SHALL exit 1 and name the install command. A worktree that holds an older version of the hooks than the installed one passes.
  - [ ] **AC8:** one argument exempts a run from AC7. It appears in `.github/workflows/ci.yml` and in the suite, and a case fails if the `- Validators:` line or a hook script carries it.
  - [ ] **AC9:** WHEN a pull request reaches CI THE SYSTEM SHALL scan, in the required job, the commits the pull request adds, its branch name, and its title and body, and SHALL NOT write that text to the log. A change to the title or body scans again. On a push to `main` it scans the pushed commits, and the whole history when the push was forced. A pull request from a fork gets the public tier over the same inputs.
  - [ ] **AC10:** a commit in this repository takes under 1 s more with the hooks than without, and a push of 100 commits under 2 s more beyond one `git ls-remote` round trip. Measured with `time` on the maintainer's machine and recorded in the ADR; not a suite case.
  - [ ] **AC11:** `CONTRIBUTING.md` says what is scanned and when, how to install the hooks, and what bypasses them (`--no-verify`, `git -c core.hooksPath=`, a clone without them) and what catches that. ADR-12 answers both of ADR-5's objections to a `pre-push` hook (installed per clone; outside both harnesses), says why CI is too late here and was not for the version bump, leaves ADR-5 standing, and lists `core.hooksPath`, CI only and a harness tool hook as alternatives. M-1's row in `docs/CONTRACT.md` names what now enforces it.
  - [ ] **AC12:** every new mode, each hook's refusal, AC6, AC7, each fault in AC3 and the removal of the guard's temporary directory on every exit has a case in `scripts/test-gates.sh`, built on synthetic patterns only. Each refusal case asserts its own fault sentence, and is shown red by removing that one check.
  - [ ] **AC13:** nothing here is shipped: the change is under `scripts/`, `.github/`, `.steering/`, `docs/` and `CONTRIBUTING.md`, with no version bump. `AGENTS.md` is not touched, because it ships as `rules/AGENTS.md`.
- Out of scope:
  - **Tracker text written with `gh`,** including the merge message `gh pr merge` writes and a tag `gh release create` makes: #361.
  - **Rewriting history,** and removing text that is already public. These checks prevent; they do not clean.
  - **Author, committer and tagger names and addresses.** See Clarifications.
  - **Text written through the GitHub web UI,** beyond what AC9 sees.
  - **A workflow on issue and comment events.** A failing run on a public repository states publicly which issue held a private word, and anyone could file issues to probe the list.
  - **Carried from #357's work log, unchanged here:** the working-tree scan does not read a symlink's target, and a misspelled section header in the pattern file is read as a pattern.
  - **Shipping any of this to projects that install the plugin.**

### Clarifications
Asked and answered 2026-11-15.

1. **One spec or two?** Two. This spec keeps the guard's modes, the git hooks and the CI scan. The tracker criterion the issue held before its edit of 2026-11-15 moved to #361, which builds on this spec's standard-input mode.
2. **Does a clone without the hooks fail the working-tree guard, or only warn?** It fails, and the turn is blocked until the hooks are installed (AC7).
3. **Are author and committer identities scanned?** No. The decision of 2026-11-13 that author names in commit metadata stay covers them, and a pattern that matched the maintainer's own identity would refuse every commit.

## 2. Design (HOW)
Every claim below marked measured was run in a scratch repository on git 2.54.0 on 2026-11-15, by the scouts and critics of this spec.

- Approach and key decisions:
  - **One guard, five inputs.** `scripts/check-leakage.sh [--public-only] [--no-hook-check] [--staged | --text | --refs | --commits <revision>...]`. Pattern loading, tier order, the text-then-bytes double pass and the closing notice are shared. Any other argument is refused as today.
  - **One regular-expression engine.** Every input becomes a file of lines in the guard's temporary directory and is read by the system `grep -E`. `git grep` is not used: measured, it never matches `\b` and it ignores a blank pattern line, so the same list would mean two things.
  - **A git command never feeds a pipe.** Each one writes to a file and its exit status is checked before the file is read. Measured: `git log … | grep -q … && exit 1` exits 0 when git dies.
  - **Git is called so the maintainer's configuration cannot change what is read.** Every call is `git --no-replace-objects -c core.quotePath=false`, and every diff adds `--no-color --no-ext-diff --no-textconv --no-relative`. Measured: `color.ui=always`, a `textconv` filter, `diff.relative` and a `refs/replace/` entry each made the stream below report clean over a commit that added the word.
  - **The git modes read the caller's repository,** not the one the script sits in, so a hook can run a guard that lives elsewhere. They do not change directory or pass `-C`: git gives a hook `GIT_DIR` and `GIT_INDEX_FILE`, and with those inherited `git -C <other checkout>` reads the caller's index (measured). The working-tree mode clears them before it changes to the script's root.
  - **`--staged`:** the paths are `git diff --cached --name-only --no-renames --diff-filter=d`. Each path's content is `git cat-file blob :0:<path>`, the whole staged file, so a symlink's target is read as text. The stage number is written out because `:<path>` reads another file when the path begins `0:` (measured).
  - **`--commits`:** the arguments are revisions, `--not` and `--all`, handed to `git rev-list`; anything else that begins with `-` is refused. An empty list is reported as empty and reaches no further command, because `git log --no-walk` with no revision prints `HEAD` (measured). Otherwise the ids go to three `git log --no-walk --stdin` runs, and the verdict comes from all three: `--format=%B` for the messages, which holds no identity; `--format= --name-only` for the paths, because an empty file has no `+++` line (measured); and `--format= -p -U0 --text`, filtered to its `+` lines, for the added lines. All three diff with `--diff-merges=separate --root --no-renames --diff-filter=d`, so content only a merge adds is seen whatever `log.diffMerges` says. Only when a tier hits is each commit read again for locations: its message, its path listing, and each added or changed file as a whole blob. A hit no location accounts for is still a failure, reported against the set.
  - **Hooks are three shims in the clone's common `hooks` directory,** which every worktree shares, with a snapshot of the guard and the hook scripts beside them in `hooks/gate-sdd/`. A shim runs `scripts/git-hooks/<name>.sh` from the worktree it was called in, and the snapshot's copy when that worktree's branch has none. It never reads another checkout's working tree, which may be behind or hold a session's uncommitted edits. Each hook script runs the guard that sits beside it, so a hook and a guard of different versions never mix. `core.hooksPath` is not used: a relative one resolves per worktree, and a worktree without the directory commits with no hook and no warning (measured).
  - **The hook scripts keep the `.sh` suffix** so they fall under `- Source globs:` and a change to one re-stales a receipt.
  - **`commit-msg.sh`** gives the message file to `--text`. With an editor that file also holds comment lines and, under `-v`, the diff: a superset, so it over-matches and never under-matches.
  - **`pre-commit.sh`** runs `--staged`. git points `GIT_INDEX_FILE` at the index of a partial commit, so the guard sees what that commit holds (measured).
  - **`pre-push.sh`** reads git's lines and skips a deletion. Field three of every other line, the name being published, goes to `--refs`. Each local id is peeled: the message of every tag object in the chain, and a blob at its end, go to `--text`; a tree is a fault. The commits go to `--commits <local ids> --not <ids>`, where the excluded ids are the commits and tags `git ls-remote <the URL git gave the hook>` lists and this clone holds. The remote-tracking refs are not used: measured, they hid unpublished commits when a remote's push URL differed from its fetch URL, and after a rewrite of the destination they hid the whole old history. A failed `ls-remote` is a fault.
  - **The absent-hooks check** runs in the working-tree mode inside a git repository, unless `--no-hook-check` is given. `scripts/git-hooks/shim.sh` carries a version line. The check fails when `core.hooksPath` is set, when a shim is missing or not executable, when the installed shim's version is lower than this worktree's, or when the versions are equal and the bytes differ. A higher installed version passes, so worktrees on different versions do not block each other. The Validators line passes no argument, so the exemption cannot be taken at turn end without editing `.steering/tech.md`.
  - **CI** scans inside the existing `Leakage guard` step, where the decoded pattern file already lives and is removed. The set is `head.sha --not base.sha` for a pull request and `after --not before` for a push; when the push was forced or `before` is not an object in the checkout, it is `after` whole. The branch name, title and body are read from `$GITHUB_EVENT_PATH` by `python3`, not passed through `env:`, because a step's `env:` block is printed in the log. `pull_request` runs on `opened, synchronize, reopened, edited`, with `concurrency` keyed on the pull request and `cancel-in-progress`. Both of the step's guard runs take `--no-hook-check`.
  - **The suite's git runs are hermetic.** Every `git` in a hook case runs with `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_DIR`, `GIT_INDEX_FILE`, `GIT_WORK_TREE` and `GIT_PREFIX` unset, `GIT_EDITOR=true`, an identity from the environment, and the synthetic pattern file. Measured: a fixture built with an inherited `GIT_INDEX_FILE` corrupted the outer commit.
  - **The history rewrite is not covered by the hooks:** a mirror clone is bare and has none. Its verification runs the guard there by hand, `--commits --all`, the ref names through `--refs`, and the annotated tags' messages through `--text`, which is why AC1 names a bare repository.
- Affected modules and files, per .steering/structure.md:
  - `scripts/check-leakage.sh`; new `scripts/git-hooks/{shim,commit-msg,pre-commit,pre-push}.sh`; new `scripts/install-git-hooks.sh`.
  - `scripts/test-gates.sh`, the leakage section. `leak_repo` holds `shim.sh` under a `.git/info/exclude` entry and installs the shims after its first commit, so the 45 existing fixtures keep their file counts; their later commits take `--no-verify`. Hook cases use a separate builder that copies `scripts/git-hooks/`. `run_leak` gives the guard `</dev/null` unless a case names an input. Case 427 (arguments) and case 428 (the CI step) are amended. New cases follow case 432.
  - `.github/workflows/ci.yml`: the trigger and the `Leakage guard` step.
  - `CONTRIBUTING.md`; new `docs/decisions/ADR-12-…`; `docs/CONTRACT.md` (M-1's row); `.steering/structure.md` (the `scripts/` row); `.steering/tech.md` only if T9 raises the budget; `docs/BACKLOG.md`.
- Contract changes, and who else consumes them:
  - The guard's argument grammar. Consumers: the Validators line (no argument, unchanged), CI, the three hooks, and #361's hook through `--text`.
  - The guard now fails in a clone without the hooks. Consumers: every session and contributor in this repository. A worktree on a branch older than this change runs its own older guard and is not affected, and the shared shims cover its commits from the snapshot.
- Risks and trade-offs:
  - **`--no-verify`, `git -c core.hooksPath=…` and a clone without the hooks** skip every hook in silence. CI is the backstop for commits and pull-request text. Nothing catches a branch or tag name pushed that way: it is public on arrival. Recorded, not closed.
  - **The hooks must be installed in the maintainer's real clone before the turn that commits T7 ends,** or that turn and every later one is blocked. The install writes to `.git/hooks` and runs only on the maintainer's go.
  - **The snapshot is a copy,** and it ages until the installer runs again. It serves only worktrees whose branch has no hooks of its own; the version check covers the shims, not the snapshot.
  - **Every push pays one `git ls-remote`,** measured at 1.9 s against this repository.
  - **After the history rewrite, a push from a worktree still on the old history is refused whole.** That is the point of the check, and each such branch has to be rebuilt on the new history first.
  - **A whole-blob second read** can name a line the commit did not add. It only runs after the verdict is already a failure.
  - **`edited` re-runs the whole CI job** on every title or body change, about four minutes each.
  - **A failing CI scan is public.** It says which pull request holds a hit, on text that is public already, with locations only.
  - **The suite has about 55 s of its 336 s budget left** (276 s measured), and forty hook cases measured about 30 s. Each hook gets one fixture with many assertions.
