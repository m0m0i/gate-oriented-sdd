# Spec: the ordered list is not told when work moves

- Slug: 79-backlog-drifts-from-the-tracker   Issue: 79   Type: bug   Status: approved
- Author: m0m0i   Date: 2026-09-20

## 1. Requirements (WHAT / WHY)

- Reproduction: three sequences, one mechanism, and none of them produces a difference any command in the repository reports.
  1. **A sprint runs.** `sprint` creates issues and writes no file (`skills/sprint/SKILL.md:16`). Read `docs/BACKLOG.md` afterwards: the rows it took still describe their work as unissued. Observed 2026-09-05 — row 1 read *no issue yet* for what was by then #76 and #77, and row 2 did not name #78 (`.specs/_archive/77-record-the-sprint-run/observations.md`).
  2. **A pull request merges and closes an issue a row cites.** The row goes on citing it as live work until someone grooms by hand. Observed five times in the day after the fifth grooming merged, and again in the day after the sixth (`docs/BACKLOG.md:17-24`).
  3. **An issue is filed outside a grooming** — from a review, or from a run of any other skill. No row names it. #176, #177, #178 and #179 entered the tracker from #26's review and reached the list only because a seventh grooming was written by hand the same day (`docs/BACKLOG.md:20`).
- Expected: `docs/BACKLOG.md` is the first thing `sprint` reads (`skills/sprint/SKILL.md:22`) and, in a `minimum`-mode project, it is the queue specs are created from — so a row that misdescribes tracker state is read as the plan before anyone checks it. `skills/backlog/SKILL.md:73` makes the tracker becoming the plan a red flag, and C-4 requires a skill to terminate in something the harness mechanically reads. Something SHALL report the difference between this list and the tracker, and the two skills SHALL name who corrects it and when.
- Actual: nothing compares them, and neither skill mentions the other's effect on the file. `sprint`'s "writes no document" (`skills/sprint/SKILL.md:16`) and `backlog`'s "groomed occasionally, not every iteration" (`skills/backlog/SKILL.md:8`) are each correct alone; together they leave the correction to the next grooming, which is by design infrequent and by observation months apart. The document is therefore false by construction from the moment `sprint` returns until a person notices.
- Impact: every project running both skills, in both modes, and worse in `minimum` mode rather than better — there the backlog is the queue, so a stale row is a spec nobody will write. Here it is the lead finding of four consecutive groomings, and the drift has outrun the grooming twice: the fifth grooming went stale in the two days between being written and being merged, and the sixth was wrong by mid-morning of the day it merged, which is why a seventh ran the same day. The cost is not tidiness — `.work_logs/` carried branch protection as owed for six entries after it was already done, and #118 closed ten hours after the list recorded it as unshipped. Work is re-argued, re-planned, and occasionally re-found.
- **Root cause:** each row of `docs/BACKLOG.md` restates two facts the tracker also holds — *which issues exist for this item* and *which of them are still live* — and nothing derives either from the tracker or compares the two. Both are therefore copies with no source. The tracker changes continuously and from three directions (`sprint` creating, a merge closing, a review filing); the document changes only when `backlog` runs, which its own preamble scopes to "occasionally". A copy that is updated on a slower clock than its subject, with no comparison between them, does not drift loudly — it drifts silently, and the reader cannot tell a current row from a stale one by looking. This is #14's and #23's class, one document over: a fact written by hand in two places with no guard between them. The missing sentence in `sprint` is why the gap opens *immediately* after a sprint; the missing comparison is why it stays open and nobody is told.
- Acceptance criteria:
  - [ ] **AC1:** WHEN an open issue exists in the tracker and is cited nowhere in the live region of `docs/BACKLOG.md` — the ordered table, any cell, plus `Unshaped` — THE SYSTEM SHALL report that issue as absent from the list, naming it.
  - [ ] **AC2:** WHEN the **Item** cell of an ordered row cites an issue that is closed, THE SYSTEM SHALL report that row as citing finished work, naming both the row's position and the issue.
  - [ ] **AC3:** the two directions SHALL read different regions, and the asymmetry SHALL be a stated convention rather than an accident: `skills/backlog/SKILL.md`'s template SHALL say that the **Item** cell names the row's live issues while `Why here` may cite any issue — including closed ones — as reasoning. Today eleven closed issues (#9, #26, #113, #118, #126, #127, #130, #131, #133, #140, #146) are cited correctly as history inside table rows, so a check reading whole rows for AC2 would report all eleven.
  - [ ] **AC4:** an open issue MAY be excluded from AC1 by an `## Open, not planned` section of the document naming it with the reason and the condition that would make it a row; THE SYSTEM SHALL read that section and SHALL NOT report an issue listed there. #36 is its first entry — open, demoted by the seventh grooming, and 100% of AC1's output against today's tree.
  - [ ] **AC5:** WHEN the check cannot reach the tracker, cannot resolve the document from `.steering/tech.md`'s `- Docs:` line, or receives an empty issue list, THE SYSTEM SHALL exit non-zero saying which, and SHALL NOT report agreement. An unreadable tracker and a list that agrees with it SHALL NOT produce the same output, and an empty issue list SHALL NOT satisfy both directions vacuously. (G-1, `- Owns: gates never fail open`.) WHEN `- Docs:` names another repository by URL — a state `assets/check-document-set.py:226-232` already recognises in a multi-repo product — THE SYSTEM SHALL say the document is not local and exit non-zero rather than treating an absent file as agreement.
  - [ ] **AC6:** WHEN the check passes, THE SYSTEM SHALL state what it examined — the number of open issues and the number of rows compared — rather than printing a bare success. (#39's class, not its decision.)
  - [ ] **AC7:** `skills/sprint/SKILL.md` SHALL instruct the run to record the issue numbers on the rows it took — a bounded, mechanical edit, not a re-groom — and its "writes no document" rule SHALL be narrowed to forbid a parallel record without forbidding that correction. `skills/backlog/SKILL.md` SHALL name `sprint`'s effect on the file and SHALL name the check as what reports the two doors no skill owns (a merge closing an issue, an issue filed outside a grooming).
  - [ ] **AC8:** the narrowed rule SHALL be pinned in `scripts/check-skill-contracts.py`, because reverting "creates no parallel record" to "writes no document" reads as concision and restores the bug.
  - [ ] **AC9:** every behaviour in AC1–AC6 SHALL have a case in `scripts/test-gates.sh` that fails before the change and passes after. Each case SHALL assert on the exit code **and** on the message naming the issue or row, so that a checker which does not exist cannot report a pass — the contract `scripts/test-gates.sh:515` already states for the same reason. No pre-existing case SHALL change verdict.
  - [ ] **AC10:** the check SHALL run in CI on pull requests and SHALL be runnable by hand, and `.steering/tech.md` SHALL record why it is not on the `- Validators:` line — it needs the tracker, so a turn-end hook cannot run it.
- Out of scope: **shipping the check to installs** — it stays in `scripts/`; the shipped form needs a `- Tracker:` steering anchor and a declared command to list issues, which front-runs #128 at row 12. Recorded below as the follow-up this spec does not file. **#174** — where a discharged row is written down; this spec settles *who* corrects the list and *what tells them it is wrong*, and whichever lands second rebases. **#164 and #165** — version lines, the `Serves` column, and the epic redefinition edit the same template. **#39** — this work must not manufacture a pass, but the project-wide vocabulary for "I checked nothing" is that issue's decision; AC6 is the shape, not the wording. **Retrospective correction of the existing table** — the seventh grooming reconciled it on 2026-09-20, and re-grooming here would make the check's first run prove nothing. **Closing or filing issues** — `backlog` creates no issues (`skills/backlog/SKILL.md:16`) and this spec does not change that.

### Clarifications

Asked and answered 2026-09-20, before any Design existed. Four questions; two of them changed section 1 by adding acceptance criteria, and all four are recorded with what the other reading would have cost.

1. **Does the check ship to installs, or is it this repository's own guard?** — *Answered: `scripts/`, repo-local first.* It joins `check-readme-claims.py`, `check-templates.py` and `check-contract-path.py`, which guard this repository's own documents and do not ship. The decisive argument is not convention but dependency: a shipped check needs a `- Tracker:` machine-read line and a declared command to list issues, and that contract is #128's territory at row 12. Keeping it local also lets the region rule (AC3) and the exemption rule (AC4) be proven here before they are frozen into something consumers copy. Rejected: `assets/` + `init` (answers C-4 for consumers, at the cost of a new steering anchor, an `init` step, and a guard whose failure modes now include no network and no auth) and a GitHub-only shipped script (bakes one vendor into a shipped path). **Cost accepted and stated: `backlog` still terminates in nothing a consumer's harness reads, so C-4 stays open for them.**
2. **Which part of a row asserts that an issue is live work?** — *Answered: the Item cell asserts; the row as a whole is generous.* Verified against the tree rather than assumed: Item cells cite **zero** closed issues today, while whole rows cite eleven, all of them correct history in `Why here`. So AC2 reads Item cells and AC1 accepts a citation anywhere. Rejected: whole-row for both directions (eleven false positives on the first run, and it would force groomings to stop citing closed issues in their reasoning — which is where the reasoning lives) and a new explicit column (unambiguous, but a table-format change to a template #164 and #174 are both already editing, and a field that can disagree with the prose beside it). **Added AC3**, because a convention the check relies on has to be written down or the check is lucky rather than correct.
3. **How does an issue get to be legitimately absent from the list?** — *Answered: a named section in the document.* `## Open, not planned`, one line per issue with the reason and the falsifier that would make it a row. The reasoning for #36 already exists in prose in **What changed at this grooming**; this gives it a machine-readable home in the document that made the decision. Rejected: an exemption list inside the guard (G-8's letter, but it hides a product judgment from every reader of the plan) and a tracker label (moves the statement into the tracker, which the backlog's own preamble says must not become the plan). **Added AC4.**
4. **Who corrects the list between groomings?** — *Answered: `sprint` appends, and the check covers the rest.* `sprint` records the issue numbers on the rows it took, with its identity rule narrowed from "writes no document" to "creates no parallel record" so the correction is permitted and a second source of truth still is not. The other two doors belong to no skill, so nothing can be instructed to write them and the check is what reports them. Rejected: guard-only with `backlog` asserting a grooming after every sprint (leaves the most predictable drift to be caught rather than prevented) and adding `implement` as a second writer (widest coverage, but it makes a second skill a writer of this document and multiplies the places a bounded edit goes wrong).

## 2. Design (HOW)

- **Fix approach, and why this rather than the narrower or wider fix.** Two halves, and the issue's own "Fix" section is only the first of them. The narrow half is prose: `sprint` step 6 gains the bounded edit and its identity rule is narrowed to match (AC7). The wide half is the guard: `scripts/check-backlog-tracker.py` compares the document against the tracker in both directions (AC1, AC2). The narrow half alone was rejected by `docs/BACKLOG.md:31` and by the evidence — it catches the sprint door and none of the nine witnesses, four of which were rows citing closed issues and one an issue that never entered. The wider fix — deriving the rows from the tracker outright — is rejected because it inverts the document: the backlog's value is the *order* and the `Why here` reasoning, neither of which the tracker holds, and a generated list is the "tracker is the plan" red flag arrived at from the other side.
- **The script's shape.** Resolves `docs/` from `.steering/tech.md`'s `- Docs:` line the way `assets/check-document-set.py:226-246` already does — including its remote-repository branch — rather than restating the path (#14's and #23's class is what this spec is about, so restating it here would be the bug in the fix). Parses the ordered table by row, splitting cells on `|` to isolate the Item cell for AC2. Reads open and closed state from `gh`, and — for AC9, since `scripts/test-gates.sh` builds throwaway repositories with no network — accepts an injected issue list through a documented override. The override is where G-1 bites: an absent, empty, or unparseable list must exit non-zero, never satisfy both directions vacuously, because "no issues" makes direction A pass with nothing to check and direction B pass with nothing to compare.
- **Where it runs, and why it blocks.** CI, on pull requests, in the `guard` job, with `issues: read`. Not on the `- Validators:` line, for a reason distinct from the two already recorded in `.steering/tech.md`: those two are judgment calls about noise and duplication, this one is a capability — a turn-end hook cannot depend on the network or on tracker auth. Blocking rather than reporting follows the precedent already in this file: `check-readme-claims.py` and `check-leakage.sh` fail a pull request on repository-wide state that has nothing to do with the branch, and have survived. PR-only, so a merge to `main` never turns `main` red on its own.
- **The residual, stated rather than discovered.** A merge that closes an Item-cited issue leaves the list stale until the next pull request, which then blocks on a one-line edit paid by whoever opened it. That is the designed cost of the list being told, and it is bounded. The precise alternative — reading the pull request's own linked issues so the closing PR must update the row in the same change — is better and is not built here: it needs the linked-issues API, and it makes `implement` a writer of this document, which clarification 4 rejected. Recorded so a later spec does not have to re-derive it.
- **Affected files**, per `.steering/structure.md`:
  - `scripts/check-backlog-tracker.py` — new, not shipped.
  - `scripts/test-gates.sh` — new cases for AC1–AC6.
  - `scripts/check-skill-contracts.py` — one needle (AC8).
  - `skills/sprint/SKILL.md`, `skills/backlog/SKILL.md` — shipped; prose and template (AC3, AC7).
  - `docs/BACKLOG.md` — the `## Open, not planned` section with #36 (AC4).
  - `.github/workflows/ci.yml` — one PR-only step (AC10).
  - `.steering/tech.md` — the third "why not on the Validators line" paragraph (AC10).
- **Blast radius.** `skills/` is a shipped path, so the change reaches consumers as prose even though the guard does not — a consumer's `sprint` will start correcting their backlog, and their template will carry the Item-cell convention and the `## Open, not planned` section with no checker behind either. That is acceptable and is the honest order (the convention is real regardless of who verifies it), but it means the version bump is a genuine release rather than bookkeeping. `check-skill-contracts.py` gains a needle, so any later rewording of `sprint`'s rule fails CI — intended, and the reason AC8 exists. Nothing reads `docs/BACKLOG.md`'s *contents* mechanically today, so the new section cannot break an existing consumer: `assets/check-document-set.py` has `BACKLOG.md` in `MANDATORY_DOCS` but tests it with `os.stat`, so it asks whether the file exists and never opens it. That checker is also already a reader of `- Docs:`, so this is the line's third reader rather than its second — and the reason the remote case in AC5 is a real state rather than a hypothetical one.
- **Why this cannot recur.** For the prose half, the needle: the sentence that permits the correction cannot be deleted without CI failing, which is the only defence against a rewording that reads as tightening. For the document half, the check itself: the class of bug is "a fact written by hand in two places with nothing comparing them", and this adds the comparison. It does not make the class impossible — the `Why here` cells still restate tracker state in prose that nothing can check, and AC3 deliberately exempts them — so the guarantee is scoped to the Item cell and the absence direction, and the spec says so rather than claiming the class is closed.
